# 跑通新成员入门说明接力

这个示例不是研发流程，也不绑定某个行业。它用一个很小但真实的任务来验证 Multigent 的核心闭环：给第一次进入工作区的新成员准备一份入门说明。

```text
Agent 接任务 -> 人类审核 -> Agent 继续接力 -> Agent 记录结果 -> 人类确认
```

如果你刚安装好 Multigent，建议先跑这个示例，而不是一上来搭自己的公司流程。

## 先理解三个概念

很多新手卡住，是因为把“流程图”和“运行”混在了一起。Multigent 里要这样理解：

```text
流程 = 可复用 SOP 地图
任务 = 一次真实工作
唤醒 = 让当前负责人开始执行
```

流程本身不会自己运行。它只定义：

- 有哪些节点；
- 每个节点应该由人还是 Agent 执行；
- 每个节点需要什么输入；
- 每个节点必须产出什么输出；
- 通过、打回、分支时应该去哪个节点。

任务才是真正运行的对象。创建任务并绑定流程后，任务会记录：

- 当前走到哪个流程节点；
- 当前负责人是谁；
- 上游节点产出了什么；
- 下一个节点要拿什么输入继续。

所以跑通这个示例的关键不是“打开流程图”，而是：

```text
配置模型账号 -> 打开已绑定流程的任务 -> 唤醒当前负责人 -> 人类审核 -> 继续唤醒下一个负责人
```

如果当前负责人是 Agent，就到 `Schedule` 手动唤醒它，或等任务触发心跳。
如果当前负责人是你自己，就到 `工作台 -> Tasks` 审核并通过/打回。

## 1. 进入 Example Workspace

首次注册后，Multigent 会自动创建一个示例工作区：

```text
Example Workspace
```

如果没有看到，可以在左上角工作区下拉里切换。

示例项目叫：

```text
hello-world-relay
```

## 2. 配置模型账号

进入：

```text
设置 -> 模型账号
```

添加一个可用账号。任选一种即可：

- Claude Code 官方账号或第三方 Anthropic-compatible 网关。
- Codex 官方账号或 OpenAI-compatible 网关。
- Cursor 账号。

保存后回到：

```text
项目 -> hello-world-relay -> Members
```

依次点开三个 Agent：

- `Lina`
- `Mira`
- `Nora`

在 Agent 详情页的“模型与凭证”里选择刚刚配置的模型账号。

## 3. 准备 Docker Sandbox

Agent 默认在 Docker sandbox 中运行。先确认 Docker 可用：

```bash
docker info
```

如果 Docker 正常，建议提前准备运行环境：

```bash
multigent sandbox prepare
```

第一次准备会拉取 runtime 镜像并安装 Agent CLI，可能需要几分钟。准备好后再运行 Agent，体验会稳定很多。

## 4. 打开初始任务

进入：

```text
项目 -> hello-world-relay -> Tasks
```

找到任务：

```text
给新成员准备一份 Multigent 协作入门说明
```

点开任务详情，可以看到它绑定了 `新成员入门说明接力` 流程。

任务详情里最重要的是三件事：

- **当前节点**：现在应该完成流程里的哪一步。
- **负责人**：这一步应该由哪个 Agent 或人类用户处理。
- **上游输出**：前一步交接过来的结构化结果，通常包含 docID 文档链接。

## 5. 触发第一个 Agent

有两种方式。

方式一：在任务详情或任务列表里手动运行当前负责人。

方式二：进入：

```text
项目 -> hello-world-relay -> Schedule
```

找到 `Lina`，点击：

```text
手动唤醒
```

`Lina` 会读取当前流程节点，创建第一版欢迎说明和交接文档，然后提交结构化输出。

执行成功后，任务不会直接完成。它会根据流程连线进入下一个节点。
如果下一个节点是人工审核，你需要去工作台处理。

## 6. 人类审核

当任务流转到人工审核节点后，当前负责人会变成你的用户账号。

进入：

```text
工作台 -> Tasks
```

或者回到：

```text
项目 -> hello-world-relay -> Tasks
```

点开任务详情，查看上游输出。如果内容可以接受，点击通过；如果不满意，填写修改意见并打回。

通过后，任务进入下一个 Agent 节点。
打回后，任务会回到上游 Agent 节点，并把你的修改意见作为输入带回去。

## 7. 继续流转

审核通过后，任务会流转到下一个 Agent：

```text
Mira
```

再次手动唤醒当前负责人，或者等待它的任务触发心跳。

后续流程会继续流转到：

```text
Nora -> 最终确认
```

## 8. 看运行结果

可以在几个地方观察：

- `Tasks`：看任务当前节点、负责人、上游输出、结构化输出。
- `Runs`：看每次 Agent 执行记录。
- `Knowledge Base`：看 Agent 创建的 docID 文档。
- `Workflows`：看流程图和节点流转设计。

## 常见卡点

### 任务没有动

通常是没有触发当前负责人。进入 `Schedule` 找到当前负责人，点击“手动唤醒”。

先看任务详情里的“负责人”。不要随便唤醒任意 Agent，只唤醒当前负责人对应的 Agent。

### Agent 运行失败

先检查：

```bash
docker info
multigent sandbox doctor
multigent sandbox prepare
```

如果是模型账号问题，回到 Agent 详情页重新选择模型与凭证。

### 看不到任务

检查当前工作区是不是 `Example Workspace`，当前项目是不是 `hello-world-relay`。

### 人类审核后没有继续

审核只是推进流程状态。下一个 Agent 仍然需要被唤醒，可以手动唤醒，也可以等待任务触发心跳。

## 重新打开产品引导

如果想再次看一遍产品引导，进入：

```text
设置 -> 开始引导
```

引导会再次带你走一遍模型账号、团队、项目、Agent、流程、任务和调度的关系。
